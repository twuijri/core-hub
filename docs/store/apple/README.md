# App Store listing for Core Hub (iPhone and iPad)

Owner's decision (2026-09-25): publish the iPhone app on the App Store. There is no Mac App Store
app; Google Play comes later. The app is `com.twuijri.corehub`, and its App Store Connect record
already exists. Builds reach TestFlight through `.github/workflows/ios-signed.yml`. Submitting a
version for review is always the owner's own step: see
[docs/RELEASING.md → App Store submission](../../RELEASING.md#app-store-submission).

## Listing

- **Name**: "Core Hub" (en-US) and «كور هب» (ar-SA), the product's own names (ADR 0017,
  `packages/contracts/src/product.ts`). Both must be free on the App Store; App Store Connect says
  so when the listing is saved.
- **Categories** (proposed — owner to confirm): Productivity, then Developer Tools.
- **Support URL**: `https://github.com/twuijri/core-hub/issues`. **Marketing URL**:
  `https://github.com/twuijri/core-hub`.
- **Privacy policy URL**: the GitHub page of `docs/privacy.md` (en-US) and `docs/privacy.ar.md`
  (ar-SA) on `main`: `https://github.com/twuijri/core-hub/blob/main/docs/privacy.md`. The repository
  is public, so the page is too. GitHub Pages is not used and was not turned on.
- **Copyright**: `2026 twuijri`.
- The description names only what the app really does (docs/STATUS.md, `apps/ios/README.md`) and
  no other company's product; the keywords repeat neither the name nor a trademark.

App Store Connect's limits, which `store-metadata.mjs` holds the files to: name and subtitle 30
characters, promotional text 170, description and release notes 4 000, keywords 100 (and, for the
Arabic list, 100 UTF-8 bytes too), each URL an `https://` address.

## Screenshots

App Store Connect's requirements, checked on 2026-09-25 (App Store Connect Help → Screenshot
specifications):

- **iPhone 6.9"** — required for an iPhone app: 1320 × 2868 (or 1290 × 2796, 1260 × 2736). The
  6.5" size is required only when there are no 6.9" screenshots, and smaller iPhones are scaled
  from these, so no other iPhone set is taken.
- **iPad 13"** — required because the app runs on iPad (`TARGETED_DEVICE_FAMILY: 1,2`):
  2064 × 2752 (or 2048 × 2732).

`ios-screenshots.yml` (Actions → iOS store screenshots → Run workflow) builds the app in Debug,
runs `StoreScreenshots` on the newest "iPhone NN Pro Max" (1320 × 2868) and "iPad Pro 13-inch"
(2064 × 2752) simulators with a 9:41 status bar, checks every picture's size, and keeps them as the
artifact `corehub-store-screenshots` for 5 days:

```
shots/light/<en-US|ar-SA>/<iphone|ipad>-01-chat.png … -06-settings.png   the store set
shots/light/<locale>/extra/<device>-00-sign-in.png                       the sign-in screen (not uploaded)
shots/dark/…                                                             with "dark" ticked (not uploaded)
```

The six pictures, in each language: a conversation (Markdown, a tool card, the thinking time), the
drawer with the chats list and profile badges, the Agents page, the Tasks board, a new chat with
its agent chips, and Settings.

**The demo hub.** The app shows real screens with made-up data and never reaches a server: started
with `-UITestDemo YES` (Debug builds only; an App Store build does not contain it), it signs in to a
hub inside the app whose every answer comes from `DemoFixtures.swift`. That file is generated by
`apps/ios/scripts/demo-fixtures.mjs`, which checks each answer against the response schema of its
operation in `packages/contracts/openapi.yaml`; `ios-store-metadata.yml` fails a pull request whose
contract change breaks them, and `DemoHubTests` decodes every answer with the generated Swift client
in the iOS unit tests. To change what the screenshots show, edit the script and run
`node apps/ios/scripts/demo-fixtures.mjs`. The same launch arguments work from Xcode:
`-UITestDemo YES -UITestDemoOpen /tasks -corehub.language ar -corehub.theme dark`.

## Uploading (never a submission)

Both upload paths use fastlane `deliver` with the App Store Connect API key (`ASC_API_KEY_ID`,
`ASC_API_KEY_P8`, `ASC_API_ISSUER_ID`, the same secrets as `ios-signed.yml`), with
`--skip_binary_upload --submit_for_review false`. They are off unless the owner
ticks `upload` on a manual run:

- `ios-screenshots.yml` with **upload**: the listing and the light screenshots of that run
  (`--overwrite_screenshots`: the sets in App Store Connect are replaced).
- `ios-store-metadata.yml` with **upload**: the listing text only.

`deliver` works on the version named by the `version` input, else the root `package.json`'s
(`1.1.0`); if App Store Connect has no such version yet, deliver creates it in "Prepare for
Submission". Neither workflow sends the age rating, the App Privacy answers, the App Review
contact or the demo account: the owner enters those in App Store Connect.

## App Privacy ("nutrition label")

Answer: **Data Not Collected.** Checked in the code on 2026-09-26:

- [x] No analytics, advertising, attribution or crash-reporting SDK. The app links only Apple's
  frameworks and `CoreHubClient`, the Swift client generated from our own contract, which has no
  dependencies (`apps/ios/project.yml`, `packages/contracts/openapi-generator/swift.yaml`).
- [x] No request to any server of the developer's: every request goes to the hub the person typed
  or scanned (`HubAPI.swift`, `RealtimeClient.swift`); no address of ours is built into the app.
- [x] Messages, attachments, the device's name, model and versions, and the push token go to the person's
  own hub. Apple counts data as collected when the developer or its partners can access it; the
  developer cannot access a hub it does not run, so this is not collection.
- [x] No tracking: no IDFA, no App Tracking Transparency prompt, no data shared with data brokers.
- [x] Push notifications go through Apple. **When the push relay is enabled** (ADR 0024, a later
  change), the relay the developer runs forwards notifications and keeps only a SHA-256 of each
  push token and which hub may use it, to deliver them; no content, no token, not linked to a
  person, not used for anything else. Our reading is that this stays "Data Not Collected"
  (proposed — owner to confirm when the relay ships; if he prefers to declare it, the entry is
  "Identifiers → Device ID, App Functionality, not linked to the user, not used for tracking").
- [x] Speech recognition with the phone's own voice is Apple's service under Apple's policy, not
  collection by the developer.

In App Store Connect → App Privacy: "Do you or your third-party partners collect data from this
app?" → **No, we do not collect data from this app**, and the privacy policy URL above.
