# sessions

Owns: `session`, `message`, `run`, `tool_call`, `approval`. Schema:
`packages/server/src/modules/sessions/schema.ts`. All scoped. Base columns
omitted.

Realtime namespace `/rt/sessions`: `run.started`, `message.delta`,
`tool_call.started`, `tool_call.finished`, `approval.requested`,
`approval.resolved`, `run.completed`, `run.failed`, `run.cancelled`.
Deltas are not persisted; the final `message` is.

## Queries the clients need

- Session list: scoped, `archived_at is null`, order by `pinned desc,
  last_message_at desc`, with agent name and the last run's status.
- Session screen: messages by `seq` (paged backwards), each with its tool
  calls and approvals by `run_id`; then subscribe to `/rt/sessions`.
- Send: insert user message → create run (`queued`) → return `{ runId }` at
  once → stream. Retry = new run, same trigger message.
- Pending approvals badge: count of `approvals where status = 'pending'`
  in the workspace (also pushed by notify).
- Stop: set `interrupt_requested_at`, call the adapter, move to `cancelled`
  on acknowledgement.
- Cost so far: ask audit for `sum(cost_micro_usd) where session_id`.
- Task/schedule/seat runs: `runs where origin_kind, origin_id`.

## Not stored

- Streaming deltas; reasoning deltas (only the final `reasoning` text).
- The agent's session file or context window; `agent_session_ref` is enough
  to resume through the adapter.
- Raw tool input containing secrets: redacted before insert; the redaction
  policy is the adapter's.
