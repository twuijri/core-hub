# زر بناء صورة يدوي في سير الإصدار
المسؤول: twuijri · الفرع: ci/manual-image · الحالة: review

## المشكلة والهدف
فتح المالك صفحة Actions ليبني صورة جديدة فلم يجد أي خيار: سير «Release» كان يعمل على
دفع وسم `v*` فقط، بلا تشغيل يدوي. النتيجة أن أي صورة معاينة تتطلب وسم إصدار حقيقي على
`main`، وهذا ثقيل لتجربة فرع.

## القرار والموافقات
- إضافة `workflow_dispatch` إلى `Release` بمدخلين: اسم وسم الصورة، والمنصات
  (`linux/amd64` افتراضًا لأنه أسرع بكثير، أو الاثنتان).
- التشغيل اليدوي **يرفض** الوسمين `latest` و`main`: هما لإصدار موسوم على `main` وحده،
  حتى لا تُستبدل الصورة التي يسحبها الناس بمعاينة فرع.
- فحص «الوسم يجب أن يكون على main» صار مشروطًا بحالة الوسم، فلا يمنع تشغيلًا يدويًا من فرع.
- `push: true` مع بوابة على مصدر التشغيل بدل الشرط القديم الذي كان يبني بلا نشر.

## العقد
لا شيء.

## الملفات والتأثير
معدَّل: `.github/workflows/release.yml`، `docs/DEPLOY.md` (فقرة «الحصول على صورة»)،
`docs/TEAM-RULES.md` (§٦ نشر صورة يدويًا). لا كود تطبيق.

## الفحوص (الأوامر ونواتجها الفعلية)
تغيير سير عمل ووثائق:

```
$ pnpm lint
All matched files use Prettier code style!

$ pnpm change-record:check
change-record  OK
```

لا يمكن إثبات نجاح التشغيل اليدوي قبل الدمج: `workflow_dispatch` لا يظهر في Actions إلا
بعد وجود الملف على `main`. أول تشغيل يدوي بعد الدمج هو الإثبات.

## المخاطر والرجوع
الخطر أن يُنشر وسم معاينة يظنه أحد إصدارًا؛ خُفِّف برفض `latest` وبأن الافتراضي اسم
`preview`. الرجوع بحذف قسم `workflow_dispatch`.

## التسليم والخطوة التالية
ينتظر دمج المالك، ثم: Actions ← Release ← Run workflow لبناء صورة معاينة من أي فرع.
