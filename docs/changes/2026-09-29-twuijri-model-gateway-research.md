# بحث: بوابة نماذج تجعل كل وكيل يعمل على أي نموذج موصول
المسؤول: twuijri · الفرع: research/model-gateway · الحالة: review

## المشكلة والهدف
طلب المالك (2026-09-29) أن يعمل كل وكيل برمجي يستضيفه الهب (Claude Code وCodex وGemini CLI وGoose وOpenCode وGrok Build وKimi Code وPi وQwen Code والوكيل المباشر وHermes) على أي نموذج أضافه الشخص مرة واحدة في الهب، دون تسجيل دخول خاص بكل مزوّد.
اليوم يمرّر الهب مفتاح المزوّد إلى وكيل المزوّد نفسه فقط، ولا يطبّق النموذج المختار على وكلاء ACP.
لذلك يفشل Claude Code برسالة «Authentication required» عند غياب مزوّد Anthropic.
هذه المهمة بحث فقط: وثيقة `docs/research/model-gateway-2026-09.md` تجمع الحقائق والتوصية.

## القرار والموافقات
- التوصية (مقترحة — بانتظار تأكيد المالك): بوابة داخل الهب مكتوبة بـ Node.
  - واجهاتها بصيغ Anthropic Messages وOpenAI Chat Completions وOpenAI Responses.
  - يصادق كل وكيل عليها برمز قصير العمر يصدره الهب لكل تشغيل.
  - توجّه الطلبات إلى المزوّدين المخزّنين في الهب، فلا تغادر المفاتيح الحقيقية الهب.
  - يُسجَّل الاستهلاك في سجل الاستهلاك الحالي.
- المرحلة الأولى: Claude Code وCodex على مزوّدين متوافقين مع OpenAI.
- تبقى تسجيلات الدخول الخاصة بكل مزوّد خيارًا كما هي اليوم.
- ملاحظة أمنية مستقلة تستحق إصلاحًا منفصلًا:
  - يرث كل وكيل ACP بيئة عملية الهب كاملة (`hostEnv.inherited`).
  - النقطة الثالثة في الوثيقة تشرح ذلك.
- لا دمج ولا نشر. طلب السحب مسودة.
