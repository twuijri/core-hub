## ماذا يفعل (في خمسة أسطر)
1. «control plane» ذاتي الاستضافة لوكلاء البرمجة: daemon محلي على الجهاز، وعملاء (macOS Electron، ويب، iOS/Android — «قريبًا» بحسب الموقع، وCLI `hubcode`).
2. يشغّل Claude Code وCodex وOpenCode وCopilot وPi وأي CLI كعمليات فرعية أصلية بمهاراتها وإعداداتها وخوادم MCP كما هي.
3. **Kanban لكل worktree**: كل git worktree بطاقة في To-do / In-progress / Ready-for-review، مع المسألة المرتبطة (GitHub، Linear، Jira، GitLab، Forgejo، Plain، Sentry) والفرع والوكيل على البطاقة.
4. **جلسات حيّة مشتركة**: دعوة زميل إلى جلسة وكيل جارية مع غرفة صوت/فيديو مدمجة أثناء العمل المشترك، وكل شيء يبقى على الـ daemon.
5. صوت محلي بالكامل (STT/TTS عبر Sherpa، كشف الدور بـ Silero VAD)، مركز MCP لكل مشروع/مضيف، حلقات «عامل + مدقّق» حتى تحقّق معايير القبول، جداول cron، اقتران أجهزة بـ QR، واتصال مباشر أو relay مشفّر طرفًا لطرف.

## الأفكار التي نتبنّاها
| الفكرة | الوحدة عندنا | كيف نطبّقها نحن |
|---|---|---|
| جلسة حيّة يشاهدها ويشارك فيها أكثر من عميل/شخص | `sessions` (`/rt/sessions`) + `rooms` | تعدّد المرتبطين بجلسة واحدة مع حضور (presence)؛ Hermes TUI gateway يدعم multi-attach أصلًا |
| صوت محلي أولًا مع مزوّدين سحابيين اختياريين | `models` (STT/TTS providers) + `devices` (media relay) | STT/TTS إعداد في صفحة النماذج؛ الجهاز يبثّ الصوت للخادم |
| اقتران بـ QR يطبعه الـ daemon | `auth` (device pairing) | عندنا أصلًا |
| بطاقة تظهر تلقائيًا لكل worktree جديد (الربط في الاتجاهين) | `board` | اكتشاف worktree تحت دليل المشروع ينشئ مهمة مقترحة |
| ربط المهمة بمسألة خارجية وتمرير سياقها للوكيل | `board` (external issue link) | حقل `issue_ref` + مزوّد لاحقًا (المرحلة 4) |
| حلقة «عامل + مدقّق» حتى القبول أو سقف التكرار | `schedules` (workflow template) | قالب سير عمل جاهز: عقدة تنفيذ ↔ عقدة تحقّق |
| اتصال مباشر أو عبر relay مشفّر | `devices` | نمط اتصال الجهاز اختيار صريح؛ لا نمرّر بيانات عبر طرف ثالث |
| مرفقات المحرّر كسياق منظّم (صور، مسائل، عناصر تكامل) | `sessions` (attachments) + `knowledge` | المرفق كيان بمعرّف يُشار إليه في الرسالة |
| كل ما في التطبيق قابل للتشغيل من CLI | `packages/contracts` | CLI مولَّد من العقد لاحقًا |

## الأفكار التي نرفضها ولماذا
- **غرفة صوت/فيديو WebRTC داخل المنتج**: ثقيلة الآن؛ ليست في أي مرحلة قبل الرابعة، وإن جاءت فعبر `devices` media relay.
- **وكيل «Hubtool» المدفوع بتوجيه متعدد النماذج**: لا خدمة وسيطة؛ `models` تدير المزوّدين مباشرة.
- **daemon لكل جهاز كبنية وحيدة**: Hermes يعمل على الخادم؛ الأجهزة اختيارية.
- **اختصارات لوحة المفاتيح وتقسيم اللوحات**: شأن العميل لاحقًا.
