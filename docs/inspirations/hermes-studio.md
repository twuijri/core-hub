# Hermes Studio / Ekko Studio (النسخة التي نشغّلها اليوم)

- المصدر: نسخة المالك الشخصية من Hermes Studio (المعروفة داخليًا أيضًا باسم Ekko Studio / Core Hub القديم).
- الرخصة: **BSL 1.1** (Business Source License 1.1؛ استخدام غير تجاري حتى 2029-05-10) — كما هو مثبّت في ADR 0004 وفي `AGENTS.md` بنسخة المالك. **لم نفتح ملف `LICENSE` ولا أي مصدر** التزامًا بقاعدة الغرفة النظيفة؛ هذه الصفحة مكتوبة من قائمة الميزات في `docs/inspirations/README.md` ومن خريطة التنقّل التي كتبناها نحن لتطبيقي الجوال (`docs/mobile/NAVIGATION.md` على فرع `mobile` في نسخة المالك).
- الحكم: **لا كود، لا أصول، لا نصوص، لا مخططات، لا ملفات لغة** (ADR 0004). المفاهيم وخريطة التنقّل ملكنا لأننا كتبناها.

## ماذا يفعل (في خمسة أسطر)
1. واجهة ويب (Vue 3) + خادم (Koa + Socket.IO) + تطبيق سطح مكتب (Electron يحزم Python/Hermes) + تطبيقا أندرويد وiOS أصليان، فوق وقت تشغيل Hermes Agent ووكلاء برمجة.
2. **مدير الوكلاء** (Agent Manager): بطاقات لوكلاء Hermes وEkko ووكلاء البرمجة (تثبيت/تحديث/حذف)، وتحت كل وكيل قدراته (Jobs، Kanban، Channels، Skills، Plugins، MCP، Memory، Journey) ثم إعداداته.
3. **الغرف** (Group Chat): محادثة يجتمع فيها عدة وكلاء وأعضاء، بأكواد انضمام؛ **سير العمل** (Workflow) بقائمة حالات؛ **السجل** (History) للجلسات بحسب المصدر مع أرشيف واختيار متعدد.
4. **اتصالات الأجهزة** (Device connections): اقتران التطبيق (مباشر / دفع الرسائل) وقائمة الأجهزة للمشرف؛ **تطبيقات الحاسوب** (computer apps) كقدرات محلية يعرضها سطح المكتب.
5. صفحة **النماذج** (General/Auxiliary/Ensembles/STT/TTS providers)، إعدادات بشرية (حساب، عرض، proxy، ضغط، خصوصية)، وأدوات: Logs، Usage، Performance، Skills Usage، Theme، Profiles؛ مع قناة تحديث «test» للعملاء.

## المفاهيم التي نُبقيها (كل مفهوم ↔ وحدة)
| المفهوم | الوحدة عندنا | ما نغيّره |
|---|---|---|
| مدير الوكلاء: سجل واحد، بطاقة لكل وكيل، «تحت الوكيل» مستوى قائم بذاته يُدخل من البطاقة ويُخرج إليها | `agents` | التوصيل عبر `AgentAdapter` لا بتوصيل يدوي لكل وكيل (ADR 0002)؛ القائمة من الخادم |
| الغرف: عدة وكلاء وأعضاء، انضمام بكود، ذكر وتسليم | `rooms` (seats, mentions, handoffs, room memory) | ذاكرة الغرفة كيان في الخادم لا في العميل |
| سير العمل وقائمة الحالات | `schedules` (cron + workflows) | DAG من runs بتعريف مجمّد (انظر `proliferate.md`) |
| اقتران الأجهزة بـ QR ورموز التطبيق؛ تبويبا App/Devices | `auth` + `devices` | كما هو؛ الأجهزة تعلن قدراتها |
| تطبيقات الحاسوب (قدرات محلية يعرضها سطح المكتب) | `devices` (capabilities, media relay) | المرحلة 3؛ عبر قاعدة `device://` عندنا |
| صفحة النماذج بتبويبات المزوّدين وSTT/TTS | `models` | إعدادات الصوت الخادمية كلها هنا |
| الملف الشخصي مرشّح محيط لا شجرة تنقّل | ADR 0005 | `X-Hub-Profile` في كل طلب |
| ثلاثة أنواع إعدادات بحسب مالك القيمة: الإنسان / وقت تشغيل الوكيل / المزوّدون والصوت | `docs/clients/NAVIGATION.md` | قاعدة إلزامية في خريطة التنقّل الموحّدة |
| Usage / Performance / Logs / Skills Usage | `audit` | شاشات مختلفة بعناوين مختلفة؛ لا يفتح مدخلان الشاشة نفسها |
| قناة تحديث test للعملاء | `updates` | قناة لكل عميل من الخادم |

## الأخطاء البنيوية التي نتجنّبها (موثّقة في تاريخ خريطة التنقّل)
1. **مداخل مكرّرة للوجهة نفسها**: `Connections` في الشريط الأساسي وفي مكان آخر؛ `Insights` تفتح ما تفتحه `Usage` و`Performance`؛ `Appearance` مقابل `Theme`؛ مدخل قائمة لـ `Global Agent` بينما الويب يصل إليه من البحث والإجراءات المعلّقة؛ «إدارة وقت التشغيل» على الهاتف بلا معنى. القاعدة عندنا: **مدخل أساسي واحد لكل وجهة**، ونص المدخل = عنوان الشاشة **بالمفتاح نفسه** في ملفي اللغة، واختبار تكافؤ يسقط عند أي انحراف.
2. **إعدادات داخل إعدادات**: شاشة «قائمة إعدادات» وسيطة على المنصتين، وقسما «متقدّم» و«أدوات مساحة العمل» في iOS، وقسم «أدوات هرمس» تحت مدير الوكلاء في أندرويد، وتبويب `Models` داخل الإعدادات يلتبس بصفحة `Models`. القاعدة عندنا: شاشة إعدادات واحدة بتبويبات، إعدادات وقت تشغيل الوكيل تحت الوكيل فقط، والمزوّدون في صفحة النماذج.
3. **مسارات مكتوبة يدويًا في العملاء**: انحرف تطبيقا الجوال عن الخادم مرتين (مسارات pet خاطئة، حقل لغة متجاهَل) لأن المسارات كُتبت باليد (ADR 0003). القاعدة عندنا: العقد مصدر الحقيقة، العملاء مولَّدون، والمسار اليدوي فشل في CI.
4. **توصيل كل وكيل بطريقته**: سبب اتساخ مدير الوكلاء (ADR 0002). القاعدة: محوّل واحد لكل نوع وسجل في الخادم.
5. **قدرات مرفوعة إلى مستوى التطبيق**: المهارات وMCP والذاكرة توجد **مرة لكل وكيل** ولا تُرفع إلى مستوى عام.
6. **ميزات تُحذف بعد نشرها** (Petdex أُزيلت 2026-09-20): نضيف الميزة إلى العقد وخريطة التنقّل معًا أو لا نضيفها.
7. **البحث مقابل السجل**: `Search` ورقة فوق الجلسات، و`History` صفحة؛ لا يُخلط بينهما.

## ما لا نأخذه تحت هذه الرخصة
BSL 1.1 (غير تجاري حتى 2029-05-10) وADR 0004: لا نسخ أي ملف أو دالة أو جدول نصوص أو أصل أو مخطط أو إعداد من Hermes Studio / Ekko Studio أو من نسخة المالك؛ لا ملفات `locales`، لا `openapi.json`، لا مكوّنات Vue، لا صور، لا صياغة وثائق، ولا اسمَي «Hermes Studio»/«Ekko». **لا يُفتح مصدرها أثناء العمل هنا.** استيراد بيانات المالك في المرحلة 5 يكون عبر أداة تصدير تُصمَّم من واجهات النسخة، لا من مخططاتها.
